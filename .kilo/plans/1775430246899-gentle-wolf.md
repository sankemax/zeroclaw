# Plan: Fix Autosave Memory Context Poisoning

> This plan addresses item #5 ("Fix cron context duplication cascade") from the Prompt Injection Investigation report: `.kilo/plans/1775420927163-eager-river.md` (see Section 12: Cron Job Context Duplication Cascade, and Section 10: Recommended Remediation Priorities). The root cause chain and filter gaps analysis are traced there.

## Problem

The autosave pipeline can recursively poison memory entries with nested `[Memory context]` blocks, causing exponential nesting over time. This is a sub-investigation item documented in the parent investigation file at Section 12.

### Root Cause (detailed in parent investigation: Section 12, Layers 1–3)

In `src/cron/scheduler.rs:283-302`, cron jobs recall memories and prepend the prompt:
```rust
format!("[Memory context]\n{ctx}\n\n[cron:{} {name}] {prompt}", job.id)
```

This prefixed prompt is passed to `crate::agent::run()` (line 307), which autosaves via `src/agent/loop_.rs:3898-3911`. The guard check:
```rust
!memory::should_skip_autosave_content(&effective_msg)
```

But `should_skip_autosave_content()` (src/memory/mod.rs:106-117) only checks `starts_with("[cron:")`, etc. The poisoned prompt starts with `[Memory context]`, not `[cron:`, so the check passes and the full content (including nested memory entries) gets autosaved.

This is the specific filter gap documented in the parent investigation: `should_skip_autosave_content` does NOT block `[Memory context]` literal content (Section 12, Filter Gaps table).

## Solution

Add `[memory context]` to the filter patterns in `should_skip_autosave_content()`.

### 1. Update `should_skip_autosave_content` (src/memory/mod.rs:106-117)

This implements fix #1 from "Recommended Fixes" in Section 12 of the parent investigation.

Add `lowered.starts_with("[memory context]") ||` to the filter chain.

```rust
pub fn should_skip_autosave_content(content: &str) -> bool {
    let normalized = content.trim();
    if normalized.is_empty() {
        return true;
    }

    let lowered = normalized.to_ascii_lowercase();
    lowered.starts_with("[cron:")
        || lowered.starts_with("[heartbeat task")
        || lowered.starts_with("[distilled_")
        || lowered.contains("distilled_index_sig:")
        || lowered.starts_with("[memory context]")
}
```

### 2. Add test for the new filter pattern

Test that content starting with `[Memory context]` is correctly skipped.

## Risk Assessment

- **Risk**: Low — purely additive filter, prevents saving synthetic context blocks
- **Impact**: Stops memory context poisoning/recursive nesting in autosave
- **Rollback**: Trivial — single line deletion
- **Side effects**: None — `[Memory context]` is a synthetic system block that should never be stored as user memory
